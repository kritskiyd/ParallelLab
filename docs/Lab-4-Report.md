# 4. Лабораторная работа № 4. Организация процесса разработки

Автор: Критский С. Д., группа 1-46М.

## 4.1. Задание

Организовать Scrum-проект, сформировать Product Backlog с уровнями Epic, Product Backlog Item и Task, подготовить документацию и инициализировать Git. Вместо Azure DevOps использованы GitHub Projects, Issues и Git-репозиторий.

## 4.2. Цель работы

Подготовить проверяемую организационную основу разработки учебно-исследовательской среды параллельных вычислений, связав потребности пользователей, релизы, спринты и техническую работу.

## 4.3. Используемые инструменты

Использованы существующий приватный репозиторий GitHub, Project на базе Iterative development, Git, REST API GitHub и браузерный интерфейс. Источники требований: POA, актуальная User Story Mapping и описание существующего кликабельного прототипа. Оригиналы предыдущих лабораторных не изменялись.

GitHub CLI в рабочем окружении отсутствует, поэтому для операций репозитория и Issues использован REST API через существующий разрешённый вход Git. API Projects ограничен правами; браузер используется для доступных настроек.

## 4.4. Создание и настройка GitHub Project

Повторное создание проекта не выполнялось. Использован [ParallelLab Scrum Development](https://github.com/users/kritskiyd/projects/1) владельца kritskiyd. Приватность сохранена, Default repository указан ParallelLab; связь также подтверждена на вкладке Projects репозитория. Переименованы существующие представления, настроены поля Priority, Story Points, Release и Iteration. Product Backlog переведён в таблицу с сортировкой по приоритету. Current Sprint и Next Sprint используют фильтры текущей и следующей итераций. Roadmap сгруппирован по Release, использует интервалы Iteration и показывает PBI.

## 4.5. Формирование Product Backlog

Созданы 10 Epic по десяти направлениям актуальной карты, 53 пользовательские истории и 10 технических Task первого спринта. Все 73 элемента являются реальными Issues; создано 63 нативных отношения Sub-issues. 31 PBI относится к MVP, 12 к Version 1, 10 к Version 2.

Истории содержат роль, действие, ценность, описание, критерии приёмки, приоритет, релиз, оценку SP и родительский Epic. Роли соответствуют POA. Использованы метки epic, pbi, task, приоритетов и релизов; нативные Issue Types в этом личном репозитории недоступны. Для выпусков созданы три milestones. Значения продублированы в нативных полях Project, а не оставлены только в тексте Issue. [Полный реестр](Product-Backlog.md) содержит прямые ссылки.

## 4.9. Результаты выполнения

Фактически созданы 10 Epic, 53 PBI и 10 Task; все 73 элемента присутствуют в Project. Проверены 63 связи Epic → PBI → Task в обоих направлениях. Сохранены приоритеты и релизы всех элементов, 53 оценки PBI и 41 назначение Iteration. Штатный TSV-экспорт после повторной загрузки страницы сверён с планом; расхождений не осталось. В каждом PBI заполнены критерии приёмки и трассировка к предыдущим материалам. Дублирующихся Issues нет.

Созданы три milestones и восемь двухнедельных итераций. Подготовлены 12 страниц Markdown-документации, README, CONTRIBUTING, .gitignore, три формы Issues и шаблон PR. Проверены 59 относительных Markdown-ссылок. GitHub корректно отображает формы Epic, User Story и Task; форма PBI содержит поля приоритета, релиза, оценки и родителя. Материалы отправлены в main.

Подтверждены восемь включённых workflows. Auto-add и начальный Backlog проверены по timeline реальных историй. Добавлено правило Item reopened → Backlog; проверены настройки закрытия Issue и объединения PR. Автоархивирование оставлено отключённым, чтобы не скрывать результаты учебного проекта. Закрытие и слияние не имитировались фиктивными Issue/PR.

Ограничение GraphQL Projects связано с отсутствием read:project/project у действующего входа. Права не расширялись; поля и представления настроены через браузер. GitHub CLI отсутствует, использован REST API. Wiki заменена Markdown-документацией, Issue Types заменены Labels. Существенных незавершённых операций по настройке нет. Не выполнялись платные изменения тарифа, создание организации или фиктивное выполнение функций. Независимый Code Review и завершение разработки не объявляются состоявшимися.

## 4.10. Выводы

Сформирована организационная модель разработки с пользовательскими историями, планом поставки и проверяемыми критериями. GitHub Projects выполняет роль доски Scrum, Issues реализуют бэклог и иерархию, Git-репозиторий хранит версионируемые материалы, docs заменяет недоступный сервис Wiki. Разделение MVP и будущих релизов сохранено: CUDA-транслятор на CPU входит в MVP, CUDA Native на GPU в Version 1.
