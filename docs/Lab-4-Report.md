# Лабораторная работа № 4. Организация процесса разработки

Критский С. Д., группа 1-46М. Актуализация: 21.10.2026.

## 1. Задание

Организовать Scrum-процесс в существующих GitHub Project и репозитории: оформить бэклог, связи, приоритеты, выпуски, спринты, доску и документацию. Исправить оформление без повторного создания исходных объектов.

## 2. Цель работы

Создать понятную систему планирования разработки учебно-исследовательской вычислительной среды, связав функции ранее созданной карты историй с реальными задачами и последовательными спринтами.

## 3. Используемые инструменты

Git, GitHub Issues, нативные родительские связи, GitHub Projects, встроенные автоматизации, Markdown, REST API и браузер. API используется для разрешённых операций с Issues; ограниченный доступ к API Projects компенсирован браузером без расширения прав.

## 4. Создание и настройка проекта

Продолжена работа в [существующем проекте № 1](https://github.com/users/kritskiyd/projects/1) и [репозитории ParallelLab](https://github.com/kritskiyd/ParallelLab). Проект переименован в «ParallelLab: разработка по Scrum», приватность обоих объектов сохранена. Переведены пользовательские поля, значения статусов и выпусков. Системный Status и другие недоступные для переименования поля не дублировались.

Переиспользованы шесть представлений: «Бэклог продукта», «Текущий спринт», «Следующий спринт», «План разработки», «На проверке», «Мои задачи». Фильтры исправлены после перевода поля спринта и меток. Сортировка по P0/P1/P2 и оценки сохранены. Восемь правил автоматизации переиспользованы; фиктивные закрытия задач не выполнялись.

> Место для скриншота 1: приватный проект, русские представления и поля таблицы.

## 5. Формирование бэклога

Сохранены 10 крупных функциональных разделов и 53 пользовательские истории: 31 в первом выпуске, 12 во втором, 10 в третьем. Исходные 10 технических задач сохранены; добавлены 10 конкретных проверок существующих функций. Итого: 83 реальных Issue и 73 родительские связи. Номера исходных задач не менялись, повторные истории и черновики не создавались.

Из заголовков и описаний удалены искусственные коды. Все истории получили единую структуру: ценность, описание, требования, критерии, приоритет, выпуск, оценка, родитель, зависимости, основание в карте и спринт. Подробный анализ первого выпуска приведён в лабораторной № 5. Все функциональные Issues остаются открытыми в «Бэклоге» до реализации.

> Место для скриншота 2: раздел с нативными дочерними историями и техническая задача с родителем.

## 8. Работа с Git

Продолжена работа в существующем локальном репозитории. Изменения документации фиксируются русскоязычным коммитом и отправляются в существующую основную ветку без принудительной отправки. Исходный код продукта не добавлялся для видимости разработки; коммит документации не закрывает функциональные Issues. Локальный и удалённый идентификаторы последнего коммита сверяются после отправки.

> Место для скриншота 5: коммит документации, основная ветка и отправленные изменения.

## 9. Результаты выполнения

Оформлены 10 разделов, 53 истории и 20 технических задач, сохранены связи. План содержит 12 спринтов и 31 историю первого выпуска. Исправлены смешанные названия, служебные коды, слишком крупные интервалы работ, несогласованные фильтры и недостаточно подробные описания. Приватность сохранена; фиктивные исполнители и завершённая разработка не заявлены.

21.10.2026 сверены фактические Issues, родительские связи, принадлежность проекту и штатный экспорт полей. Подтверждены 83 из 83 элементов проекта, 73 родительские связи, 53 оценки и 51 назначение спринта. Все 83 строки совпадают с планом, все Issues открыты и находятся в «Бэклоге». Проверены 85 относительных ссылок документации, циклов зависимостей нет. Активные автоматизации переименованы по-русски и проверены по сохранённым назначениям статусов.

Ограничения: системные надписи оболочки GitHub не переводятся из проекта; сроки предварительные, существенные открытые вопросы требуют согласования до разработки. Закрытие, слияние и выпуск не имитировались для получения скриншотов.
