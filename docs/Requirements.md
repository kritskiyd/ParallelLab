# Требования к программному продукту

## Основание

Требования перенесены из раздела 2 существующего отчёта и актуальной карты пользовательских историй с десятью действиями. Каждое требование реализуется через PBI с проверяемыми критериями. [Реестр и номера Issues](Product-Backlog.md) содержит трассировку, оценки и связи.

## Функциональные требования MVP

| Область | Проверяемый результат | PBI |
| --- | --- | --- |
| Эксперимент | Создание, проверка формата, открытие и единый контекст рабочей области | M01–M03 |
| Код | Просмотр, правка, сохранение нескольких реализаций; просмотр сгенерированного C++17 | M04–M06 |
| Технология | Sequential C++, OpenMP, MPI и CUDA-транслятор / CPU | M07–M10 |
| Параметры | Размер задачи, повторы, потоки, процессы, Grid и Block | M11–M13 |
| Окружение | Наличие и версии компилятора, OpenMP, MPI Runtime и транслятора; понятная диагностика | M14–M15 |
| Сборка и запуск | Актуальный код, консоль, остановка, различимые ошибки и CPU-конвейер CUDA | M16–M19 |
| Серия | План, перебор параметров, повторы, прогресс и отмена | M20–M22 |
| Результаты | Базовая история, детали, устойчивое сохранение условий и результатов | M23–M25 |
| Анализ | Сопоставимость данных, ускорение, эффективность OpenMP/MPI и базовый график | M26–M29 |
| Система | Характеристики и неизменяемый снимок для каждого запуска | M30–M31 |

Базовая история относится к MVP. Version 1 добавляет поиск и расширенные фильтры истории, а не переносит базовый журнал из MVP. CUDA Native не является обязательным условием приёмки MVP.

## Общие ограничения и качество

- Корректность: тестовые задачи имеют известный результат; факт компиляции не считается проверкой вычислений.
- Воспроизводимость: запись связывает ревизию кода, входные данные, параметры, режим и снимок аппаратно-программных условий. Равенство времени при повторе не гарантируется.
- Безопасность выполнения: пользовательский код выполняется отдельным процессом; нельзя обещать полноценную песочницу без её реализации и проверки. Аргументы передаются без конкатенации shell-команд. Отмена завершает дерево процессов.
- Надёжность: ошибки чтения, записи, сборки и выполнения явны; устаревшие артефакты не выдаются за новые.
- Интерфейс: сохраняется существующая desktop IDE-компоновка и продуктовая навигация; документация дисциплины не входит в UI. Изменения проверяются в тёмной и светлой темах.
- Анализ: времена сравниваются для одной задачи и исходных данных. S = Tseq / Tpar; E = S / p, где p задаёт потоки OpenMP или процессы MPI. Нельзя применять эту интерпретацию к логическим CUDA-потокам как к физическим ядрам GPU.

Численные пороги производительности и результаты пользовательского тестирования не выдумываются. Требуемые показатели уточняются с участниками пилота до приёмки.

## Поздние релизы

Version 1 содержит CUDA Native, GPU-диагностику, шаблоны, историю кода, сохранённые настройки, экспорт и дополнительные графики. Version 2 содержит совместную работу, удалённые и распределённые запуски и расширенную аналитику. Полный состав: [Roadmap](Roadmap.md).

## Приёмка

На Sprint Review демонстрируются конкретные критерии Issue. Приёмка MVP требует полного пути от создания до повторного открытия результатов и анализа. Данные интерактивного прототипа показывают компоновку и переходы, но не доказывают готовность исполнения или фактическую скорость программы.
