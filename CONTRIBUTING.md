# Правила работы над проектом

Перед началом прочитать [руководство разработчика](docs/Development-Guide.md) и [организацию Scrum](docs/Scrum-Process.md). Использовать существующие Issues, родительские связи, приоритеты и поле «Спринт». Не создавать повторную пользовательскую историю для технической части.

Для изменения нужны понятная цель, критерии приёмки и согласованные зависимости. В запросе на слияние указать Issue, выполненные проверки и ограничения. Сообщения писать по-русски, сохраняя названия технологий. Заполнять фактические результаты, не отмечать критерии выполненными заранее.

Репозиторий и проект приватные. Не добавлять секреты, персональные данные или материалы учебных отчётов в интерфейс приложения. Не включать CUDA Native и удалённое выполнение в первый выпуск без согласованного изменения границ.
